# The gate for the RLM campaign

Written 2026-11-10, before any campaign unit ran on a GPU. **Do not edit this file after the
run.** The campaign records its sha256 in `campaign.jsonl` (`begin`, under `files`) before
the first unit starts, next to the hashes of the campaign code and of spec-ptc's sources.

*Published copy: wording about the working process was removed after the runs, so this
text no longer hashes to the sha256 the campaign recorded. No prediction, bound or rule
was changed ([README](../README.md#design-and-testing)).*

## The question

After spec-ptc's streaming mode, how much of an RLM session is left for more speculation to
hide?

The earlier runs settled how speculative calls should be queued. This run decides whether
the other half, how aggressive speculation is, is worth building: launching calls behind
conditions and early exits, a shadow that never stalls, wider peeks. All of those can only
move tool work earlier. None can shorten the root's own writing.

## The metric

For one finished task in the `stream` arm:

    after-stream share = sum over turns of (shadow_wait_s + exec_s) / task wall time

- `shadow_wait_s`: from the end of the root's stream until spec-ptc's shadow has finished.
- `exec_s`: the real run of the turn's code blocks, which claims the speculated calls.

Both are logged per turn (`events.jsonl`, kind `root_stream`). The share is the part of a
session spent after the root has finished writing a turn, waiting for that turn's results.

It is an upper bound on what any policy inside a turn could still save. It also contains
time no speculation removes: calls whose arguments need an earlier call's result, and local
compute.

## The rule

A cell is the `stream` arm at one concurrency (8 or 4). Its value is the median share over
its finished tasks. A cell is valid with at least 12 finished tasks (of 16 planned).

- Go if any valid cell is at 0.15 or above. Next step: split the remainder into true
  dependencies, shadow stalls, calls behind conditions or early exits, and calls that were
  never speculated. Build nothing before that split.
- No-go if both cells are valid and both are below 0.15. Then there is no
  speculation-policy work to do on OOLONG, and the ceiling is the result. Check one
  search-style workload before concluding anything about code mode in general.
- Unresolved otherwise (too many failed tasks). Fix the cause and rerun the `stream` arm.

`rlm_campaign.py` computes the verdict (`gate`) and prints it in `summary.md`.

## Reported next to it, not part of the rule

- The same share for `nospec` (all the tool time) and `fanout`.
- The pooled share (total time over total time) and the median's bootstrap 95% CI.
- Task wall time of `stream` against `nospec` and `fanout`, paired by task and repeat.
- Wasted speculation: evicted over dispatched calls.
- Root TPOT by arm, and the engine's queue, preemptions and KV peak.

## Limits known before the run

- Small: 8 tasks, 2 repeats per cell, one model, one H100.
- Trajectories differ between arms and repeats (sampling temperature is the model's
  default), so task wall times are noisy. The share is a ratio inside one arm, which is
  why the rule uses it and not a speed-up.
- OOLONG is label-then-aggregate. Its programs are mostly maps over chunks. A low share
  here says little about workloads with scan-until-found loops or conditional follow-ups.
- No simulator predictions were made for this run: the simulator has not modelled
  RLM trajectories.
- Speculation across turns is outside the metric. Guessing a later turn's calls could
  hide time the share does not count.
